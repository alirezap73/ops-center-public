# داداش — مدیریت پروژه‌ها

این نسخه با [مجوز MIT](LICENSE) منتشر شده است.

پلتفرم ماژولار برای پیگیری، مستندسازی و بررسیِ بخش‌های مختلف هر پروژه — ساخته‌شده با **Next.js** + **React** + **Supabase (Postgres)**.

هر پروژه (مثل فروشگاه نمونه یا وبلاگ نمونه) شامل چند «ماژول» است. هر ماژول یک وضعیت (شروع‌نشده / در حال انجام / نیاز به بررسی / مسدود / انجام‌شده)، یک اولویت، یک یادداشت آزاد برای مستندسازی، و یک چک‌لیست بررسی دارد. علاوه بر آن یک **تقویم محتوا** جداگانه برای وبسایت/تلگرام/اینستاگرام دارد (ایده → پیش‌نویس → زمان‌بندی‌شده → منتشر شده، با تاریخ انتشار). همه‌چیز در دیتابیس واقعی ذخیره می‌شود و فقط با ورود (ایمیل magic-link) قابل دسترسی است. حالت روشن و تیره هم پشتیبانی می‌شود.

---

## ۱. ساخت پروژه در Supabase

1. وارد [supabase.com](https://supabase.com) شو و یک پروژه جدید بساز (رایگان کافیست).
2. برو به **SQL Editor** → **New query**، محتوای فایل `supabase/schema.sql` را کامل کپی و اجرا کن.
   این فایل جدول‌های اپ، سیاست‌های Row Level Security و زمان‌بندی بکاپ روزانه را تنظیم می‌کند.
3. برو به **Authentication → Providers** و مطمئن شو **Email** فعال است (پیش‌فرض فعال است). چون از روش magic-link استفاده می‌کنیم نیازی به تنظیم رمز عبور نیست.
4. برو به **Authentication → URL Configuration** و آدرس سایتت را (مثلا `https://ops.yourdomain.com`) به‌عنوان **Site URL** و آدرس `https://ops.yourdomain.com/auth/callback` را در **Redirect URLs** اضافه کن (برای توسعه محلی `http://localhost:3000/auth/callback` را هم اضافه کن).
5. برو به **Settings → API** و دو مقدار زیر را کپی کن:
   - `Project URL`
   - `anon public` key

## ۲. تنظیم پروژه روی سیستم خودت

```bash
npm install
cp .env.local.example .env.local
# مقادیر NEXT_PUBLIC_SUPABASE_URL و NEXT_PUBLIC_SUPABASE_ANON_KEY را در .env.local بذار
npm run dev
```

سایت روی `http://localhost:3000` بالا می‌آید. اولین بار که ایمیلت را وارد کنی، یک لینک ورود برایت ایمیل می‌شود؛ روی آن کلیک کن تا وارد شوی.

بعد از اولین ورود، داشبورد خالی است. با دکمه‌ی **«پروژه جدید»** در سایدبار اولین پروژه‌ات را بساز و بعد ماژول‌ها، محتوا، آپدیت‌ها و بقیه را داخلش اضافه کن.

هر کسی که ایمیل خودش را وارد کند، با همان magic-link وارد می‌شود؛ اگر کاربر جدید باشد Supabase Auth حساب او را می‌سازد. داده‌ی کاربران در یک PostgreSQL مشترک نگهداری می‌شود، اما RLS روی هر ۱۱ جدول بر اساس `auth.uid()` آن‌ها را کاملاً از هم جدا می‌کند. پس یک نصب می‌تواند چند کاربر مستقل داشته باشد و هیچ کاربری به داده‌های دیگری دسترسی ندارد.

برای ثبت‌نام عمومی، در Supabase از مسیر **Authentication → Providers → Email** گزینه‌ی ساخت کاربر جدید باید فعال باشد. آدرس نسخه‌ی آنلاین نیز باید در **Authentication → URL Configuration** به‌عنوان `Site URL` و در `Redirect URLs` ثبت شود.

## ۳. دیپلوی روی هاست

راهنمای نصب در مسیر `/self-host` سایت است. کد این نسخه در [مخزن عمومی GitHub](https://github.com/alirezap73/ops-center-public) قرار می‌گیرد. این نسخهٔ قابل انتشار، داده‌ها و تنظیمات خصوصی نصب‌های دیگر را ندارد؛ فایل‌های `.env.local` و خروجی‌های دیتابیس خودت را هرگز commit نکن.

این اپ Next.js 14 به **اجرای دائمی Node.js** نیاز دارد؛ هاست PHP یا فایل استاتیک به‌تنهایی کافی نیست. روی سرور یا هاست سازگار، پس از دریافت مخزن و تنظیم دو متغیر `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `npm ci`، `npm run build` و `npm run start` را اجرا کن. متغیرهای `NEXT_PUBLIC_*` باید پیش از build تنظیم شده باشند. برای دامنه از HTTPS و reverse proxy استفاده کن. اگر cPanel داری، فعال بودن قابلیت Node.js و امکان build/اجرای دائم را از هاست بپرس.

دیتابیس و ورود کاربران همچنان در پروژه Supabase خودت هستند؛ نصب اپ روی هاست شخصی، دیتابیس را خودکار به همان هاست منتقل نمی‌کند.

## ۴. ساختار پروژه

```
app/
  layout.js            ← layout اصلی (RTL، فونت‌ها)
  page.js              ← لندینگ عمومی معرفی محصول
  guide/page.js        ← راهنمای عمومی و قدم‌به‌قدم استفاده از پنل
  dashboard/page.js    ← داشبورد محافظت‌شده + واکشی داده‌ها
  login/page.js        ← صفحه ورود با ایمیل magic-link
  auth/callback/route.js ← تبادل کد ورود با نشست Supabase
  globals.css
components/
  LandingPage.jsx      ← رابط لندینگ عمومی و معرفی قابلیت‌ها
  GuidePage.jsx        ← آموزش بخش‌ها، بکاپ و سؤال‌های رایج
  OpsCenter.jsx        ← کل رابط کاربری و منطق تعامل با Supabase (Client Component)
lib/supabase/
  client.js            ← کلاینت Supabase برای مرورگر
  server.js            ← کلاینت Supabase برای Server Components
middleware.js          ← تمدید خودکار نشست ورود در هر درخواست
supabase/
  schema.sql           ← تعریف جدول‌ها (projects, modules, checklist_items, content_items) و RLS
```

## ۵. تقویم محتوا

بالای صفحه‌ی هر پروژه دو تب هست: «ماژول‌ها» و «تقویم محتوا». در تب تقویم محتوا می‌تونی برای هر پروژه آیتم محتوا بسازی — با پلتفرم (وبسایت/تلگرام/اینستاگرام)، وضعیت (ایده/پیش‌نویس/زمان‌بندی‌شده/منتشر شده)، متن یا کپشن، و تاریخ انتشار. مثل ماژول‌ها، روی هر آیتم کلیک کن تا باز بشه و قابل ویرایش باشه.

## ۶. افزودن پروژه/ماژول جدید

- از سایدبار روی «پروژه جدید» بزن تا یک ردیف جدید (مثل yamix.io یا dad.exchange) اضافه شود.
- داخل هر پروژه، روی «ماژول جدید» بزن تا یک بخش تازه (مثلا «تست امنیتی»، «صفحه بلاگ») اضافه کنی.
- روی هر ماژول کلیک کن تا باز شود: وضعیت و اولویت را با کلیک تغییر بده، یادداشت بنویس (روی خروج از فیلد ذخیره می‌شود)، و آیتم‌های چک‌لیست را اضافه/تیک بزن.

همه‌ی این تغییرات مستقیماً در دیتابیس Supabase ذخیره می‌شوند — چیزی در حافظه مرورگر نمی‌ماند.

## ۷. بکاپ خودکار

`supabase/schema.sql` یک کار زمان‌بندی‌شده در Supabase Cron می‌سازد که هر روز
ساعت ۶ صبح به وقت دبی از اطلاعات هر کاربر snapshot می‌گیرد. جدول
`user_backups` برای هر `user_id` فقط یک ردیف دارد؛ بنابراین اجرای جدید با
`UPSERT` جای نسخه‌ی قبلی را می‌گیرد. آخرین نسخه از بخش «بکاپ» سایدبار قابل
دانلود است و خروجی‌های دستی SQL و JSON نیز همچنان در دسترس‌اند.
